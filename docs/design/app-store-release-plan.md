# Portfolio Agent：App Store 发行与订阅方案

更新：2026-10-23。用户计划：个人开发者账号，中国大陆优先发行。

本文件补充并约束 [1 万日活后端重构方案](backend-ios-10k-dau-plan.md)。只规划，不修改已确认 UI、不购买服务、不接受协议、不提交审核。依据当前官方资料形成工程方案；苹果审核、当地资质认定和服务供应条件仍须实际核实，不能保证上架结果。

## 1. 先解决主体与功能边界

个人开发者账号并不因“使用订阅”本身而不能收费，但 App 的具体服务可能要求其他主体和资质。苹果审核指南 3.2.1(viii) 涉及金融投资/理财服务，5.1.1(ix) 涉及受监管服务或敏感用户信息的提交主体；不能据此承诺个人账号一定能发布当前完整产品。[官方审核指南](https://developer.apple.com/app-store/review/guidelines/)

**项目判断：当前方案存在实质性的主体/资质前置问题，应先澄清，再形成付费发布承诺。** 这不等于所有投资记录工具都必须是持牌金融机构，也不等于注册普通公司就自动取得投资咨询资格。纯记录/统计工具的具体归类需要结合实际数据处理与功能，而不是仅看 App 分类或名称。

已有后端 `agent/system_prompt.py` 明确要求给出仓位调整建议；`save_recommendation` 支持加仓/减仓，Watchlist 包含建仓价格区间。即使 iOS 目前只显示复盘，直接复用这些能力也可能输出个性化投资指令。仅添加“不构成投资建议”不能改变实际提供的服务。

| 路径 | 产品范围 | 发布条件与取舍 |
| --- | --- | --- |
| 个人主体下的收窄候选 | 手工账本、持仓/历史数据展示、客观收益统计；AI 仅在核实可提供后用于事实摘要与概念解释 | 仍需核实金融/敏感信息分类，尤其云端持仓数据；不能称为已确认可上架 |
| 保留完整云端投资分析产品 | 已规划的云端组合、个性化分析、新闻监测及付费问答 | 建议组织主体筹备，并核查所需资质或真实持牌合作；普通营业执照不代替金融服务许可 |
| 当前开发阶段 | 按既定 UI 完成工程与内部测试 | 可以先用个人开发者身份推进开发，TestFlight 也有审核，不把测试分发当作公开运营豁免 |

用户尚未批准缩减功能或变更主体，因此本轮只提出候选范围，不擅自删除 Ask Agent、新闻规划或修改会员承诺。

先准备产品说明、完整交互录屏、AI 输入输出样例、数据流与服务商清单，向 App Review 提前说明具体功能；必要时预约沟通。咨询反馈有助于判断，不是预先批准。苹果也明确要求相关金融应用提供资质/合作材料。[完整审核材料说明](https://developer.apple.com/cn/help/app-review/before-submitting-for-review/complete-review/)

如后续选择组织主体，按 Apple 的账户流程申请转换；不要先随意更换 Bundle ID 或新建不兼容账号。组织主体、App 备案、数据服务合同、会员收款和隐私政策的运营方应一致或有明确授权关系。[Apple 注册与主体转换说明](https://developer.apple.com/help/account/membership/program-enrollment/)

## 2. AI 服务必须有真正的范围控制

这是针对个人主体候选版本的工程建议，不能替代资质结论：

- 可设计为历史记录汇总、收益构成说明、资产类别/币种占比和公开概念解释；输出使用可核验数据与时间。
- 在资质未明确前，不将具体证券买卖时机、目标价格、个性化加减仓比例、保证收益、跟单或组合自动调仓作为公开服务。
- 即使关闭 `save_recommendation`，自由文本仍可能产生建议，因此要同时改提示词、工具白名单、结构化输出、回复检测和对抗评测；不能仅隐藏建议卡片。
- 对“今天该买哪只”“替我挑基金”“卖多少能回本”等问题说明当前服务范围，并提供相关事实或通用知识，不生成伪装成复盘的交易指令。
- 每个 AI 输出可反馈问题，后台有处理队列；输入/输出做必要内容审核。SSE 采用可审核的分段输出，避免先流出越界内容再撤回。
- 服务范围同时作用于移动端、日报/周报 Worker、MCP/A2A、新闻摘要；不能让外部协议绕过限制。

后端新增 `ai_policy_profile` 与内容评测版本，执行时取服务端已发布配置；评测包括普通询问、诱导越界、提示注入、错误收益引用和第三方内容中的伪指令。尚未审查的能力不通过远程开关偷偷开放。

中国证券监管公开说明将软件提供具体证券投资分析、预测或买卖时机等纳入关注范围；本项目是否构成受监管投资咨询，需要按最终功能与收费方式核实。这也是不能仅靠“不下单”判断无需资质的原因。[证监会投资者答复](https://www.csrc.gov.cn/csrc/c100028/c1002326/content.shtml)

## 3. 国内发行：与 Apple 审核并行的三条线

### 3.1 App 备案

对拟在境内提供互联网服务的 App，按适用要求办理 APP 备案并提供对应信息；App 名称、主办者等元数据与备案一致。网站备案不能直接视为 APP 备案已完成；备案与经营许可也不是同一件事。付费业务的主体/许可适用性另行确认，不从“个人可备案”推出“所有订阅业务都可经营”。[工信部 APP 备案通知](https://www.miit.gov.cn/jgsj/xgj/wjfb/art/2023/art_dd783a581c9644a4aee10afa582811db.html)

### 3.2 新闻与第三方内容

Apple 的中国大陆发行说明列出了新闻内容许可要求，并要求适用的备案信息匹配。持仓新闻监测应列为待核实项，不能因为入口藏在复盘里或内容由 AI 摘要就认为自动排除；公司公告与授权新闻的边界也需要结合具体内容确认。数据供应商允许调用 API，不等于应用方具备全部内容传播资质。[Apple 中国大陆发行信息](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information)

工程上维护 `content_rights_registry`：供应商、允许内容类型、展示/摘要/缓存/推送范围、有效期、地域、原始来源、证据文件。新闻功能尚不具备发布条件时不能作为正在销售的 Pro 权益；可继续内部开发，待满足要求后正式发布。不得用站外链接引导来掩盖缺失许可。

### 3.3 生成式 AI

使用已经备案的模型 API 不等于应用自身已经完成全部手续。网信办公告区分模型服务备案与直接调用已备案模型能力的应用/功能登记，并说明公示要求。应向属地主管部门核实本产品适用的流程，保存服务商与模型版本、备案/登记依据。[网信办 2026 年公告](https://www.cac.gov.cn/2026-09/14/c_1791136833136332.htm)

按适用的生成合成内容标识要求，设计 App 内 AI 标识、导出/分享时的标识及必要元数据，不能把“非投资建议”当作 AI 标识。具体标识格式随适用标准实现。[生成合成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

正式上线前，对金融服务、新闻内容、APP/AI 手续和数据出境分别给出适用性结论。当前未声称其中任何一项已完成；这是发行工作包，不阻止先完成可复用技术基础。

## 4. 订阅产品：先把付费合同设计清楚

首发中国大陆版本采用 StoreKit 自动续期订阅开通 App 内数字服务，不设计支付宝/微信付款码、网页开通按钮、联系客服收款或自建激活码。海外不同 storefront 的例外不直接套用到中国大陆版本。会员收费对象是持续提供的分析/内容服务，而不是 APNs 通知本身。[审核指南 3.1 与 4.10](https://developer.apple.com/app-store/review/guidelines/)

建议一个订阅组，Pro 月付与年付位于同一权益等级；只卖一套完整且已上线的权益。具体价格待成本与服务范围明确后确定。

| 权益 | 免费 | Pro | 设计约束 |
| --- | --- | --- | --- |
| 手动持仓、客观统计 | 保留 | 保留 | 基础用户价值 |
| 收盘总结、每周复盘 | 保留 | 保留 | AI 生成部分需相关授权与可发布条件 |
| 每报告追问 | 3 次 | 不限次数 | 不把失败重试、断网恢复重复计次 |
| Ask Agent | 可浏览介绍/历史，发送时检查权益 | 支持 | 开放范围依据第 1–2 节，不默认等于投顾 |
| 持仓新闻内容 | 不包含新增监测 | 具备许可/授权后才纳入 | 未正式提供前不写入付费商品承诺 |
| 系统通知 | 用户可选择 | 用户可选择 | 拒绝通知不影响已购内容在 App 内访问 |

“不限次”需要后端和预算确实支撑；可明确同一会话仅一个并发、合理请求速率等服务规则，但不能隐藏每日总次数上限。价格不可持续时先调整新销售方案并按平台规则处理既有订阅，而不是收款后默默停用服务。

首发可暂不提供免费试用，降低产品状态复杂度。若引入试用，使用 StoreKit 的资格判断与官方商品配置，展示试用期限、后续总价和续费周期。月年方案同组防止重复购买；订阅在支持的设备上恢复。[Apple 订阅设计说明](https://developer.apple.com/app-store/subscriptions/)

收费准备：Account Holder 完成有效 Paid Apps Agreement、收款与税务信息；首次订阅产品随对应 App 版本提交，填写产品本地化和审核截图。不要在资料未齐全时将模拟购买当成可售商品。[付费协议](https://developer.apple.com/help/app-store-connect/manage-agreements/sign-and-update-agreements/)、[首次 IAP 提交](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-in-app-purchase)

## 5. iOS 订阅页与后端状态机

### 5.1 UI 补充，不推翻当前视觉

现有 `SubscriptionView` 只是演示开关，生产需要替换为真实付费页：

1. 清晰展示 Pro 包含的服务，月付/年付、当地币种价格、实际扣款总额和续订周期；年费不能只突出折合月价。
2. 价格读取 StoreKit 商品，不从后端手写币种符号或按人民币换算其他商店价格。
3. 提供购买、恢复购买、管理订阅，以及隐私政策、使用条款链接；关闭页不影响免费功能。
4. 购买中、用户取消、等待批准/付款、验证中、已开通、失败可重试分别显示；不能购买失败却显示会员。
5. “我的”展示权益截止时间和自动续订状态；取消续订与到期区分。
6. 删除“体验订阅版”的生产入口；演示仅位于明确标识的独立样例模式/非生产构建，不能修改真实权益。

### 5.2 服务端权威状态

执行链：登录绑定用户 → 获取真实商品 → StoreKit purchase → 已验证交易同步后端 → 校验并持久化 store transaction + entitlement → 回传权益 → 完成交易处理。监听 Transaction.updates，启动与恢复时读取当前交易状态。交易处理步骤幂等，网络中断可续办，不丢失已购买权益。

| 状态/事件 | 服务行为 |
| --- | --- |
| purchase cancelled / pending | 不新开权益、不重复收费；持续监听后续结果 |
| verified active | 按有效期授予权益；再次同步返回同一结果 |
| auto-renew disabled | 当前已支付周期继续有效 |
| grace period | 仅在实际配置并由 Apple 交易状态确认的宽限期内继续服务 |
| billing retry without grace | 不把所有重试状态都视作会员有效，按真实期限判断 |
| expired / revoked | 对未来受限服务收回权益；保留用户账本和已有内容的合理可访问性 |
| refund event | 基于已验证交易和 Apple 状态重新计算，不依赖一个回调字段盲目开关 |
| upgrade/downgrade/跨设备恢复 | 以订阅组与有效交易状态重算，避免出现两套叠加账单或旧权益覆盖新权益 |

验证内容包括证书/签名、bundle、app、product、environment、transaction、期限、撤销和 appAccountToken。生产交易与 sandbox 使用隔离命名空间。送审安装包必须正确接受 Apple 审核产生的有效 sandbox 交易，在隔离的测试账本中授予可完整审核的会员服务，不能因为后端部署在生产环境就一律拒绝 sandbox。测试用户/交易/报告全链路隔离，不计真实收入，也不与正常客户的生产权益混用；同一购买流程和服务能力应可验证。

V2 回调先验签并持久化，再响应；通知 UUID 和交易 ID 双层去重，乱序触发重算；定期拉取订阅状态/通知历史对账。密钥只在后端密钥管理服务中。沿用主方案的 Outbox、重试和审计机制。

App 用户与 Apple 交易的绑定冲突应有清晰恢复流程：一个 Apple 购买不能任意绑定多个应用账户，但同一用户换设备/重装不能被错误剥夺权益。账户删除后的重建只在可验证交易归属和明确恢复流程下处理，不复活旧私人数据。

后台“会员管理”是查看、对账、排错和受控服务补偿，不模拟代用户购买/取消/退款，也不售卖后台开通资格。正常促销使用 Apple 官方优惠能力；需要退款时提供系统申请渠道，最终结果由 Apple 处理。客服操作记录原由、对象、有效期和执行人，不共享总管理员 token。

## 6. AI 数据授权要进入任务调度层

Apple 5.1.2(i) 明确要求在向第三方 AI 分享个人数据前披露并取得明确许可。登录、购买会员、接受总条款都不自动等于同意把持仓发给模型。[审核指南的数据使用条款](https://developer.apple.com/app-store/review/guidelines/)

建议第一次启用云端 AI 时给出简短独立说明：实际服务商/受托方、会发送的字段、用途、处理地点、已核实的保留与训练政策，并提供同等清晰的同意/暂不启用。别承诺供应商“绝不保存/训练”，除非合同与配置支持。

把处理范围分为交互问答与后台定期复盘/新闻分析；允许一次清晰授权覆盖持续处理，不要求每个 token 弹窗，但必须说明定时任务会在 App 未打开时运行。变更服务商、地域、用途或数据范围时按适用要求更新授权。自动故障切换只使用已在授权范围内的服务商。

后端新增：

- `consent_records`：用户、用途、供应商范围、字段范围、说明版本、授权/撤回时间。
- `privacy_policy_versions` / `processing_registry`：已发布说明与实际数据处理链一致。
- Worker 在认领任务和真正外发前都检查当前授权/账户状态；撤回后停止尚未外发的任务，不能只在入队时检查一次。
- 问答仅发送当前问题所需数据；不发送手机号、Apple 身份 token、APNs token、账户备注等无关字段。外部搜索仅使用必要公开标的/事件关键词。
- 未获授权时不调用模型，仍允许记账、确定性统计与读取已有内容；不强制允许广告/训练/无关分析来解锁已购功能。付费前说明云端 AI 的必要处理，避免先收款才告知用户。
- 训练用途默认不启用；若未来另加数据改进计划，需要独立的可撤回选择，不能与核心功能绑定。

## 7. 隐私、账户删除与备份恢复

### 7.1 数据清单

按实际处理填写 App Privacy，覆盖自有服务与第三方 SDK。当前云端计划可能涉及用户 ID、资产/持仓等财务信息、购买记录、聊天内容、诊断与使用信息；金融数据不能因为“手工输入”就不申报。Apple 收取的银行卡信息不等于本 App 收集了银行卡，分别判断。[Apple 隐私标签定义](https://developer.apple.com/app-store/app-privacy-details/)

上线核对 PrivacyInfo.xcprivacy、实际使用的 required-reason APIs 和第三方 SDK 的签名/清单。每个声明要有代码或 SDK 依据，不为“通过审核”填无关理由。[Privacy Manifest 文档](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files)

首发不引入广告跟踪或广告 SDK。分析只记录最少事件，不记录持仓金额/聊天正文；隐私政策、商店标签、SDK 实际行为、AI 授权说明四者一致。以后引入跨 App 广告跟踪时另行评估 ATT，AI 授权不是 ATT 的替代品。

### 7.2 账户删除是一条完整业务流程

“我的 → 账户与隐私 → 删除账户”可以发起真实删除；不是仅退出、冻结或强制联系客服。允许必要重新认证与确认。账户删除与 Apple 订阅取消是不同流程：提示剩余周期和续费，提供管理订阅入口，同时保留立即删除选项；不能要求等订阅到期才允许删除。[Apple 账户删除说明](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion)

工程设计：`deletion_requests` + 分阶段任务 + 最小化删除凭证。

1. 重新认证，展示将删除的账本/报告/会话以及依法确需保留的数据类型和期限；可先导出，但不把导出作为删除前提。
2. 接受请求后立即阻止新写入、撤销应用会话/MCP 授权、取消定时生成与推送绑定；撤销 Sign in with Apple 相关 token。
3. 清理 PostgreSQL 私人业务记录、Redis 私有缓存、对象文件、向量/全文索引、未完成队列、日志副本和供应商侧可删除记录。不能只删 users 行。
4. 开发期间定义并测试完成时限；只有全部必要步骤完成才标记 completed，失败可恢复并向用户说明进度。
5. 交易/审计若确有法定保留要求，单独最小化隔离，记录依据和期限；不以“财务应用”为由永久留存所有持仓/聊天。
6. 备份不能把已删用户重新带回线上。备份设保留期；恢复流程在对外服务前重放删除清单，确保数据不会复活。删除清单不保存完整私人内容。
7. 删除后收到 Apple 回调仅更新依法/履约必要的最小交易记录，不重新创建账本或恢复旧用户资料。

需要 API：`GET /me/privacy`、`PUT /me/consents/{purpose}`、`POST /me/export-requests`、`POST /me/deletion-requests`、删除进度查询；这些操作不因用户没有会员而被锁住。

## 8. 通知与内容质量

日报/周报/新闻通知由用户主动选择。默认锁屏文案只提示报告就绪，不显示资产金额、亏损或交易细节；关闭通知仍可在复盘页看全部已生成内容。真正有内容才通知，休市日若提供回顾要如实标注。

用户希望提升使用频率，不转化为强制通知或把营销混入财务提醒。若未来增加优惠营销通知，独立选择、可关闭；不把开启通知作为购买或领取服务的条件。

摘要必须包含可追溯来源/时间，AI 解释与确定性计算分开。报价数据不足时显示缺失，付费文案不能承诺无依据的实时覆盖。新闻重要性判断保留理由；不要反复推同一事件制造焦虑或暗示保证收益。

## 9. 审核可访问性与交付材料

当前原生版本是 UI MVP：固定行情/报告、本地演示回答、假会员状态，没有真实登录、StoreKit、APNs、隐私/删除流程。可以作为设计基线，不能当作正式收费构建提交。

首个正式送审版本至少准备：

- 使用真实服务链路的稳定构建；样例模式明确标识，不能针对审核人员偷偷切换不同业务行为。
- 完整审核路径：新增持仓、报告、追问、Ask Agent、购买、恢复、管理订阅、AI 拒绝/同意/撤回、账户删除。提供受控测试身份或全功能样例模式，不暴露真实用户数据。
- 后端、模型和数据服务在审核期间可访问；中国大陆发行不意味着可以让审核人员因网络位置完全无法测试。区域限制如实说明。
- 覆盖免费、已订阅、已到期状态的测试方式，以及首次订阅产品审核材料。审核账号与真实生产客户隔离，且无需获取某个私人手机号验证码才能完成审核。
- App 图标、真机截图、本地化说明、支持和隐私 URL、EULA、联系信息、准确年龄分级、加密出口合规回答，以及适用的资质/内容授权材料。
- 明确声明所有核心外部服务、实际可用功能与地域差异；远程配置只控制已披露的发布/降级，不用来审核后开启未披露金融功能。

上述审核路径与材料遵循 Apple 的完整审核指引，不能把说明文档替代可实际操作的功能。[完整审核材料说明](https://developer.apple.com/cn/help/app-review/before-submitting-for-review/complete-review/)

## 11. 对实施顺序的修订

1. 先确定发布主体与具体服务范围，尤其是否保留个性化投资建议及新闻服务；无需推翻已确认 UI，但会影响模型能力和会员售卖内容。
2. 并行建设可复用的多用户账本、PostgreSQL、API 与任务系统；从第一天加入 consent、deletion、subscription、audit 的数据边界。
3. 在真实 AI 前完成用户授权，在收费前完成 StoreKit 的完整生命周期，在公开发行前完成适用资质与内容权利。
4. 首批功能按实际可交付范围销售；未来增加新闻或更深入分析时，经产品、资质、用户授权和审核流程更新，不靠静默开关绕过。

建议当前采用“个人账号推进开发，公开收费发布路径先核实”的决策。若完整产品范围必须保留，应尽早评估组织主体与实际资质安排；若坚持个人主体公开发行，则需要另行确认是否接受收窄功能。本文件没有替用户作出这项产品决定。
