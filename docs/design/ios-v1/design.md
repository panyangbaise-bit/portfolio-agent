# Portfolio Agent · iOS 第一轮交互设计

日期：2026-10-21；视觉修订：2026-10-22。状态：可评审视觉与交互稿，未连接生产服务。

## 已确定的产品边界

- iOS 成为面向用户的主要界面。迁移完成后，现有 Streamlit 只承担后台管理。
- 复用现有 Python 账本、计算、Agent、报告、记忆和调度能力；不是把后端改写为 Swift。
- 第一版仅手工录入持仓和交易。没有图片、邮件、文件导入、快捷指令或券商同步。
- 只开放可自动获取最新市场报价或官方净值的具体标的。基金按净值发布时间更新；不以估值冒充官方净值。
- 目标资产包括 A 股、基金、港美股、黄金；不含 Crypto。黄金必须对应具体产品；本稿以黄金 ETF 展示。
- 此阶段不验证供应商、授权或行情覆盖。稿中标的、价格、收益、来源内容均为演示，不代表已验证支持。
- MCP 保留现有能力，不新增首版用户界面。

## 信息架构

底部四个入口：总览、持仓、复盘、我的。

1. 总览：统一复盘窗口展示自动送达的最新内容，接持仓市值、累计盈亏和资产配置。不设单独周复盘栏或底部订阅功能卡片；Ask Agent 改为顶部品牌栏的轻量对话入口。
2. 持仓：已持有与关注列表、标的详情、初始持仓手工录入、手工买卖、持仓与行情更新时间。
3. 复盘：报告列表、可追溯的报告详情、投资记忆、带当前报告上下文的 AI 追问。
4. 我的：订阅权益、展示币种、涨跌配色、每日与每周通知、账户管理入口及产品信息。

手机端不暴露执行轮数、工具调用参数、模型配置、cron、索引状态或原始运行日志。报告证据仍对用户可见。

## 已选定：复盘优先

- 用户已选定复盘优先，取消首页方向切换。
- 收盘总结与周复盘到时自动进入同一个复盘窗口，以最新送达内容为主。首页不常驻单独的周复盘栏，历史内容统一在底部「复盘」页查看。
- 复盘卡片只显示类型、日期、标题、摘要与详情入口，不展示阅读时长或追问次数。报告内的追问权益不变，进入问答流程后展示额度。
- 报告库支持全部、收盘总结、每周复盘筛选。每份报告可查看依据、标记已回顾和追问；全部列表也保留已推送的新闻摘要。
- 开通订阅后自动获得持仓新闻推送。服务端决定内容与发送时机，摘要出现在首页复盘窗口，点击跳转事件详情；不设新闻检查页面、主动检查按钮或首页固定入口。
- 顶部 Ask Agent 入口打开独立全屏问答，隐藏品牌栏和底部导航。免费状态可浏览欢迎页，发送问题时进入订阅说明。报告追问继续附着于对应报告。

原型保留持仓、录入、详情和设置流程，以及紧凑列表、空组合及行情异常状态设计控件。

## 视觉规范（按当前 Portfolio Agent 统一）

用户已明确要求 iOS 与当前 Portfolio Agent 使用相同的 UI 风格。视觉依据为 `app/styles/cyberpunk.css`、`app/styles/theme.py` 和当前 `docs/screenshots/dashboard.png`。虽然文件名保留 cyberpunk，实际生效样式已是 Alpha Arena 风格；早期霓虹主题文档不作为本次依据。

- 固定白色背景 `#ffffff`、黑色文字和结构线 `#000000`、次级文字 `#666666`、次级分隔线 `#cccccc`。
- 主按钮黑底白字；链接、当前选项强调与图表主线使用蓝色 `#0000ff`。保留 P / A 品牌标识，斜杠为蓝色。
- 盈亏默认绿涨 `#00aa00`、红跌 `#cc0000`，与当前网页相同；始终配合正负号，可在设置中切换。
- IBM Plex Mono 用于英文和数字，中文回退 PingFang SC；预览内置字体并附 SIL OFL 许可，原生端应随 App 打包；系统等宽字体作为兜底。标题 28pt/700，主要数字 27–34pt/500，正文 14–16pt，辅助信息 11–13pt。
- 直角卡片、按钮、输入框、状态标签；指标框 2pt 黑边，普通容器 1pt 黑边，无阴影。仅设备外框、系统 Home 指示条和 iOS 开关保留圆角。
- 固定浅色与现有网页一致，宿主深色模式不会把产品界面变为另一套主题。
- 内容边距 16–20pt，交互命中区至少 44pt。布局适配手机，保留四个底部入口。
- 报告追问附着于具体报告；独立 Ask Agent 使用顶部轻量入口，不使用全局悬浮聊天覆盖主要内容。

## 本轮可点击范围

四个底部入口；总览金额隐藏；持仓/关注切换；标的详情；受支持标的搜索；手动新增初始持仓；手动买卖；日报与周报筛选、详情及证据；每报告 3 次追问与用尽状态；订阅演示切换及不限次追问；顶部 Ask Agent、订阅后自动送达的新闻摘要与详情演示；每日/每周推送设置与通知预览；空组合与过期行情状态。

原型中的录入、对话、额度和订阅状态仅在当前预览内存中生效，重载恢复示例。AI 回答是预置演示。没有真实系统推送、订阅购买或新闻轮询。初始持仓记录与实际买入事件区分。金额隐藏覆盖总览，设置文案不承诺全局隐私模式。

## 关键交互规则

### 手动建立持仓

从已支持标的搜索选择 → 查看报价类型与所属日期 → 填写账户、数量、单位成本、持仓截至日期 → 保存。未知标的不允许任意创建；报价中断时阻止新增。相同账户相同标的提示去已有持仓记录买卖，避免重复。

本轮沿用现有模型要求填写成本；未来允许未知成本需先明确指标缺失语义，不能用 0 成本代替。数量、成本、交易价格须为有限正数；卖出不超过已有数量。

### 价格状态

区分价格所属时间、获取时间、市场休市、净值等待公布、接口异常。休市/等待次日净值属于正常状态。接口异常保留最后有效价格、标记过期；不得以成本替代现价并展示为正常市值。

### 复盘

展示报告覆盖日期、所用持仓截至时间、价格/净值覆盖范围。事实、计算结果与解释分层。已有持仓快照不等于已知完整历史交易；缺少现金流时不提供完整收益率或因果归因。

本稿的周报使用完整的虚构样例（期间无资金进出），用于说明归因布局。新增持仓不会自动改写已生成报告；报告保留原数据截点。本轮首页不展示历史市值曲线。

### 每日收盘总结与推送

- 收盘总结关注最新估值变化、持仓贡献、配置变化和数据覆盖。周复盘关注整周表现、配置及历史决定。
- 各市场收盘与基金净值并不同步；分别标注报价所属日期、时区和报告截点。混合时点展示为“本轮估值变化”，不冒充同一交易日收益。
- 产品目标是每天触达一次，实际发送须由用户开启通知并获得系统授权。当前默认方案为北京时间 08:00，可修改；用户分别控制每日总结与周复盘。
- 多市场合并一条日常提醒。每周复盘暂定周一送达，与当日总结合并；仅开启周复盘时也使用所选时间。
- 全部持仓市场休市时发送简短投资回顾，明确没有新行情，不制造涨跌或重复分析。部分市场交易时，仅说明实际更新部分。
- 推送默认不显示资产金额，点击直达对应报告。尚无持仓时不生成虚构报告。数据不足时说明缺口；生成失败不发送“报告已就绪”。正式实现需记录通知状态、避免重发和多端重复提醒。

### 免费与订阅权益

| 能力 | 免费用户 | 订阅用户（后续） |
| --- | --- | --- |
| 收盘总结、每周复盘阅读与推送 | 支持 | 支持 |
| 围绕报告追问 | 每份报告各 3 次 | 不限次 |
| 独立 Ask Agent | 订阅入口 | 支持 |
| 持仓新闻持续监测（news poll） | 订阅权益中说明 | 开通后自动推送 |

“3 次”按每份报告独立计算：当天收盘总结和当周周复盘分别拥有 3 次，不共享额度。推荐问题点击发送也计一次；仅阅读、打开会话、标记已回顾不消耗次数。成功获得回答才计次，失败和重复请求不扣次数。

额度用完后，保留报告、证据和已有回答；发送区替换为额度说明和订阅入口。重新进入、换设备、重新开会话或修订同一份逻辑报告均不重置次数。新一期报告获得新的 3 次。付费期间不扣免费额度，回到免费状态后使用原先剩余额度。

正式服务需按用户与逻辑报告持久化额度，校验订阅状态，采用请求幂等和并发额度预留，回答失败释放预留。客户端只负责显示，不能靠隐藏按钮限制权益。原型仅演示成功回答及本地额度变化。

Ask Agent 和新闻监测先作为订阅规划呈现，价格与购买流程未确定。报告内追问绑定报告及其证据；独立问答可跨持仓、历史交易与投资记忆。新闻推送开通后随持仓更新范围，记录事件来源与日期；服务端决定哪些事件值得推送及发送时机，客户端展示收到的摘要和详情，不要求用户主动检查。系统通知权限关闭不阻止已生成内容进入复盘窗口与历史列表。当前原型使用明确标注的虚构事件，未接入新闻或服务端推送。

## 功能复用与必要补充

| 手机端功能 | 现有实现 | 复用方式 / 缺口 |
| --- | --- | --- |
| 组合金额和盈亏 | `domain/valuation.py`，`app/views/dashboard.py` | 复用计算；抽出应用接口，排除成本兜底冒充现价 |
| 标的类型 | `domain/instruments.py` | 复用 CN namespace 消歧；增加面向用户的标的目录与可用状态 |
| 持仓/买卖 | `db/models.py`、`db/repository.py`、`app/views/holdings.py` | 复用模型与交易计算；新增账户归属、用户隔离、幂等移动端写入接口 |
| 初始持仓 | 当前新增时自动写一笔当前时刻 buy | 必须调整为初始快照/期初事件，不能假定今天买入；与历史交易重放协调 |
| 关注列表 | `WatchlistItem`、`app/views/watchlist.py` | 迁入持仓内的关注分段，不单占底部入口 |
| 报告 | `AgentSession`、`AnalysisChart`、`list_analysis_runs`、`get_agent_session_detail` | 复用报告存储与证据，移动端呈现独立于后台执行信息 |
| 自动周复盘 | 当前盘后分析与月度复盘任务 | 周频模板/任务及用户偏好是新增能力，不能标为已实现 |
| 每日收盘总结 | 当前分市场盘后分析任务 | 复用触发与分析能力；补用户级每日汇总、多市场截点、休市内容与去重推送 |
| 报告追问 | `agent/`、`app/components/ask_agent_chat.py` | 复用 Agent 会话能力；补报告上下文、异步/流式接口及每报告 3 次额度 |
| 订阅权益 | 尚无移动端订阅体系 | 新增权益校验、额度账本及购买/恢复流程；当前不接入支付 |
| Ask Agent / news poll | 现有问答与新闻轮询能力 | Ask Agent 提供独立问答入口；news poll 由服务端决定推送并写入统一内容流，补用户隔离、订阅校验及监测范围 |
| 投资记忆/决定 | `memory/`、`UserAction`、建议与历史页面 | 进入复盘的记忆和决定记录；记录“已回顾”不能等同买卖执行 |
| 历史市值曲线 | `PriceCache` 等基础 | 现有组合历史快照与资金流覆盖不足，需补快照与口径后上线 |
| 通知 | `notifier/` 当前 Telegram | iOS 推送需新增，不将 Telegram 视为 APNs 实现 |

## 后台最终保留

任务配置与执行记录、Agent 调用审计、行情源与标的目录管理、数据修复、用户/账户权限管理、记忆索引运维、服务配置与监控。用户/账户后台当前也需补建。

迁移期间保留原网页可用；逐项完成 iOS 接口与端到端验收后，才撤下对应用户页面。无需现在删除原页面。

## 视觉到代码的顺序

1. 首页方向已确定；本轮完善收盘总结、每日推送、报告追问额度和订阅状态。
2. 固化视觉 token、组件和加载/空/错误状态；补足账户管理、交易历史、完整记忆检索界面。
3. 使用 SwiftUI 搭建相同信息架构，先用本地演示数据形成原生可运行外壳。
4. 在现有 Python 后端提取移动端应用接口，再依次连接组合、持仓、交易、报告、记忆与问答。
5. 完成逐项迁移后，把 Streamlit 收敛为后台。

本次不修改生产业务逻辑、不验证行情、不宣称 SwiftUI App 已完成。

## 原生实现进展 · 2026-10-23

已在 `ios/PortfolioAgent.xcodeproj` 落地 SwiftUI 本地 MVP，并在 iPhone 18 Pro / iOS 27 模拟器运行。包含统一复盘首页、持仓录入/买卖、报告/追问、顶部 Ask Agent、订阅及新闻摘要演示、偏好与本地保存。11 项核心测试通过，重启后持仓和额度保留。详细能力与限制见 `ios/README.md`。此版本尚未接入真实报价、AI、云端报告/推送和收费，原 Python 后台及数据未改动。

Ask Agent 原生页面参考「蚂小财」的独立对话布局：顶部返回、标题和会话菜单；中部留白、欢迎语、三条推荐问题及换一换；底部快捷问题与固定输入区，随键盘上移。沿用黑白蓝、直角和等宽字体。支持新对话、历史会话、旧记录迁移与本地恢复。当前不加入语音或附件。该原生页面更新先于 HTML 视觉原型，以原生实现为准。
