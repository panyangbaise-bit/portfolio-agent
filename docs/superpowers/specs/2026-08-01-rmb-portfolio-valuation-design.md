# 人民币统一组合估值设计

## 目标

修复仪表盘将人民币、美元和港币直接相加的问题。A 股以人民币计价；美股和加密资产以美元计价；港股以港币计价。仪表盘的总资产、总成本、盈亏金额和盈亏率全部以人民币计算。持仓表保留报价与成本的原币种，只将市值转换为人民币。

## 架构

新增独立的汇率服务模块，作为唯一的货币换算入口：

- `CNY -> CNY` 始终返回 `1`，不发网络请求。
- `USD -> CNY` 与 `HKD -> CNY` 通过 ExchangeRate-API 的免密钥端点 `https://open.er-api.com/v6/latest/{base_currency}` 取得实时汇率。
- 汇率请求与现有报价请求一样设定短超时并缓存 60 秒，避免阻塞仪表盘首屏。
- 每个成功结果会保留为进程内最近成功值。刷新失败时使用该值；没有成功历史时，估值使用原币金额并记录警告，避免崩溃或伪造汇率。

汇率服务接受可注入的请求函数，使其无需访问网络即可做确定性测试。

## 数据流

1. 仪表盘读取持仓及现有的原币种报价快照。
2. 价格获取层根据持仓市场批量取得所需的 `USD/CNY`、`HKD/CNY` 汇率。
3. 估值辅助函数将每笔 `shares * price` 与 `shares * cost_basis` 转换为人民币。
4. KPI 使用人民币成本与人民币市值计算总资产、盈亏金额、盈亏率。
5. 持仓表保留原始 `Cost` 和 `Price`，并用市场对应符号显示；`Market Value` 显示为人民币。

## 展示规则

| 市场 | Cost / Price | Market Value | 顶部资产与盈亏 |
| --- | --- | --- | --- |
| CN | `¥` | `¥` | `¥` |
| US | `$` | `¥` | `¥` |
| CRYPTO | `$` | `¥` | `¥` |
| HK | `HK$` | `¥` | `¥` |

单笔 P&L 百分比仍由原币种 `price / cost_basis` 得出；同一标的中汇率因素不改变该百分比。组合 P&L 百分比从人民币总市值与人民币总成本得出。

## 错误处理

- 单个汇率请求失败不会阻断报价刷新或页面渲染。
- 有最近成功汇率时继续估值并记录日志。
- 首次启动且无汇率可用时，不显示外币持仓的人民币市值，并将顶部人民币汇总标记为不可用；日志会明确标注缺失的货币。绝不把原币金额伪装为人民币。
- 无外币持仓时不请求汇率接口。

## 测试

- 验证 CNY、USD 和 HKD 成本与市值按给定汇率合计为人民币。
- 验证组合盈亏与百分比基于人民币金额。
- 验证持仓表仅为 Cost / Price 添加对应币种符号，而 Market Value 显示人民币。
- 验证汇率服务的 60 秒缓存、最近成功值回退及 CNY 免网络请求。

## 不在范围内

- 不修改数据库 schema，也不将汇率写入历史价格缓存。
- 不修改持仓录入、交易流水或 Agent 工具的原币种语义。
- 不尝试将历史交易成本重新换算；仪表盘实时使用当前汇率进行统一估值。
